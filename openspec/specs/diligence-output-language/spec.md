## Requirements
### Requirement: One diligence output language
The system SHALL expose one supported output-language selection for an entire diligence workflow and SHALL support exactly `en` and `zh-CN` in the first release.

#### Scenario: Interactive deal defaults from UI locale
- **WHEN** a user creates a deal from a Simplified Chinese or English interface without overriding the output language
- **THEN** the deal output language is initialized to the validated active UI locale

#### Scenario: Non-interactive creation remains deterministic
- **WHEN** a service, import, or older client creates a deal without an output language
- **THEN** the deal output language defaults to `en`

#### Scenario: Unsupported language is rejected
- **WHEN** a caller submits a language outside `en` and `zh-CN`
- **THEN** the API rejects the request without changing the deal or creating a draft

### Requirement: Immutable per-draft language snapshot
The system SHALL persist the selected language on each memo draft and SHALL use that snapshot as the authoritative language for every asynchronous stage and retry in that draft.

#### Scenario: Browser locale changes during a run
- **WHEN** a Chinese draft is queued and the user later changes the interface to English
- **THEN** queued, resumed, and retried stages continue generating Chinese output

#### Scenario: First draft snapshots the deal
- **WHEN** the first workflow stage creates a draft for a deal
- **THEN** the draft records the deal's current output language in the same creation flow

### Requirement: Full-pipeline language propagation
The system SHALL apply the draft language to natural-language content generated by ingestion synthesis, Research, Checklist and Q&A, expert-validation questions and synthesis, scoring rationale, memo drafting, and rendering.

#### Scenario: Chinese diligence run
- **WHEN** a draft language is `zh-CN`
- **THEN** generated summaries, findings, questions, rationales, attention explanations, headings, and memo prose are Simplified Chinese

#### Scenario: English diligence run
- **WHEN** a draft language is `en`
- **THEN** generated summaries, findings, questions, rationales, attention explanations, headings, and memo prose are English

#### Scenario: Mixed-language evidence
- **WHEN** source documents or expert responses contain both Chinese and English
- **THEN** generated analysis uses the draft language while verbatim quotations and provenance remain in their original language

### Requirement: Stable machine and evidence contracts
The system MUST preserve machine-readable schema keys, enum tokens, identifiers, citation references, proper nouns, and verbatim source evidence independently of the selected output language.

#### Scenario: Structured Chinese output
- **WHEN** a Chinese stage returns structured JSON
- **THEN** JSON keys, enum values, dimension IDs, source IDs, and citation IDs remain valid under the existing schemas while narrative values are Chinese

### Requirement: Non-destructive language versioning
The system SHALL update language in place only before generated artifacts exist and SHALL create a new linked draft version when the requested language differs after any artifact exists.

#### Scenario: Change before generation
- **WHEN** a partner changes language on a draft with no generated artifacts
- **THEN** the deal preference and draft snapshot update without creating another draft

#### Scenario: Change after generation
- **WHEN** a partner confirms a different language after any generated artifact exists
- **THEN** the system creates a new latest draft linked to the source draft, resets the active workflow for regeneration, and leaves the source draft unchanged

#### Scenario: Finalized version remains immutable
- **WHEN** a partner requests another language for a finalized memo
- **THEN** the system creates a new draft version and does not modify the finalized draft or its artifacts

#### Scenario: Same-language request is idempotent
- **WHEN** a partner selects the language already active on the latest draft
- **THEN** the system creates no new draft and returns the unchanged state

### Requirement: Compact localized language control
The system SHALL present one accessible deal-level language control and SHALL not ask for a language separately at each workflow stage.

#### Scenario: Switch before generation
- **WHEN** a user selects another language before artifacts exist
- **THEN** the control saves the selection immediately and all stage views reflect the active choice

#### Scenario: Confirm version generation
- **WHEN** a user selects another language after artifacts exist
- **THEN** the UI explains that a new language version will be generated and the current version will be preserved before performing the change

#### Scenario: Responsive keyboard operation
- **WHEN** the control is used on mobile or with a keyboard
- **THEN** it remains reachable, labelled, operable, and contained within the deal header

### Requirement: Backward-compatible migration
The system SHALL treat pre-existing deals and drafts as English without rewriting their stored generated artifacts.

#### Scenario: Existing finalized English memo
- **WHEN** the migration encounters a finalized draft without language metadata
- **THEN** it records `en` and leaves all memo content, timestamps, finalization state, and provenance unchanged
